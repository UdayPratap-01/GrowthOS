## 1. Executive Summary

### Overall integration health

GrowthOS has a **real, multi-provider integration architecture** — not stubs. OAuth flows, encrypted token storage, tenant-scoped `Integration` rows, capability matrices, canary/autonomous gates, and read-only verification harnesses exist for Meta and Google Ads. SEO intelligence (GSC M9.3) is the most mature Google integration path.

However, the platform is **not production-ready for commercial multi-client agency SaaS** without remediation. Several integrations contain **sunset API versions** that will fail against live providers, critical OAuth/discovery gaps block Meta lead routing, WhatsApp is acknowledge-only, GA4 is minimally tested, and the tenant model lacks a first-class **Website / External Account** hierarchy required for agency productization.

### Major blockers (P0)

| # | Blocker | Platform |
|---|---------|----------|
| 1 | **Google Ads API v18 is sunset** (official sunset 2025-08-20); all 6 code paths still call `googleads.googleapis.com/v18` | Google Ads |
| 2 | **Meta lead enrichment uses Graph API v19.0**, sunset 2026-05-21 per official changelog | Meta |
| 3 | **Meta OAuth does not persist `page_id` / page tokens** — lead webhooks cannot route post-connect without manual config | Meta |
| 4 | **No hosted production infrastructure** (Postgres, Redis, S3, TLS, workers) | Platform |
| 5 | **Live provider credentials and App Review incomplete** for Meta/Google production accounts | Meta, Google |

### Major risks (P1)

- Google Ads still **requires `GOOGLE_ADS_DEVELOPER_TOKEN`** for connect readiness despite official Sept 2026 developer-token sunset (token now optional/ignored but Cloud project access level is authoritative).
- Meta Graph **v21.0** in use; official removal scheduled **2027-01-21** — upgrade path needed.
- **No Website entity** — integrations attach to `(organization_id, client_id?)` only; SEO site URLs are duplicated strings across models.
- **WhatsApp webhooks**: signature-valid but **no message ingestion or tenant routing**.
- **AI metering gaps**: `ai_tokens` recorded but not quota-enforced; inconsistent `requires_quota` across routes; global provider keys (no BYOK).
- **No cross-provider 429/quota exhaustion handling** except GSC org rate limit.

### Safe-to-keep components

- `Integration` model + Fernet encrypted `secret_ref` via `persistence.py`
- HMAC-signed OAuth state (`oauth.py`) with org/client/user binding and 15-minute TTL
- Meta/WhatsApp webhook HMAC-SHA256 verification (`webhooks.py`)
- SSRF protection for SEO/competitor crawlers (`seo/ssrf.py`, `SafeFetcher`)
- Canary + production gates for ads mutations (`canary.py`, `production_gates.py`)
- SEO action review-only executor (`SeoActionExecutor` — no live CMS publish)
- GSC intelligence pipeline (M9.3) with idempotent sync and org rate limits
- Startup checks blocking mock AI, SQLite, local storage in production

### Required change categories

| Category | Examples |
|----------|----------|
| **Code changes** | Google Ads v18→supported version; Meta lead API version; Meta page discovery; quota/retry layer |
| **Credentials** | Meta app prod credentials, Google Cloud OAuth client, Cloud project Ads API access level |
| **Provider approval** | Meta App Review (`ads_management`, webhooks), WhatsApp Business verification, Google Ads Cloud project production access |
| **Infrastructure** | Managed Postgres, Redis, S3, TLS, worker deployment, public webhook HTTPS |

### Authentication & 2026 access model

| Aspect | Current implementation | Official Sept 2026 model |
|--------|------------------------|--------------------------|
| OAuth 2.0 | Google OAuth with offline refresh | Unchanged — [Authentication](https://developers.google.com/google-ads/api/docs/oauth/overview) |
| Developer token | **Required** in `credentials_configured()`, sent as `developer-token` header | **Sunset 2026-09-09** — optional/ignored; access level on **Google Cloud project** — [Developer token FAQ](https://developers.google.com/google-ads/api/docs/api-policy/developer-token), [Cloud-managed access](https://developers.google.com/google-ads/api/docs/concepts/no-developer-token) |
| Cloud project approval | Not checked in code | `CLOUD_PROJECT_NOT_APPROVED_FOR_PRODUCTION` error in v25+ for TEST access on prod accounts |
| login-customer-id | Optional env `GOOGLE_ADS_LOGIN_CUSTOMER_ID` | Correct for MCC — [Login customer ID](https://developers.google.com/google-ads/api/docs/concepts/call-structure#cid) |

**Verdict:** Code still treats developer token as mandatory gate. Must modernize to Cloud Console **Google Ads API Overview** access-level model while upgrading API version.

              └── ExternalAccount[]
                    ├── external_id (act_*, customer_id, channel_id, waba_id)
                    ├── display_name
                    └── resources[] (campaigns, properties, phone numbers)

**Rules M10.1 must enforce:**

4. Webhook routing keys (page_id, waba_id, phone_number_id) must map to ExternalAccount → Client
5. All integration upgrades (Google Ads v25, Meta v25+) must land before or with M10.1 schema migration
6. SEO M9.1–M9.16 data remains org-scoped; migrate `site_url` fields to reference Website.id
